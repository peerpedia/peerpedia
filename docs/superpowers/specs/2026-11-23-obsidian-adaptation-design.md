# Peerpedia 的 Obsidian 本地写作适配

日期：2026-11-23。状态：用户已于本次对话确认定稿，已完成独立实施可行性审阅；没有开始产品实现。

## 目的与产品边界

用户从开始写作时就以在 Peerpedia 发表文章为目的。Obsidian 是本地写作工具，文章未发表只是工作阶段，不另设私人笔记转论文的产品流程。

网站已经取消在线写作，负责发布、阅读和协作评审。插件负责本地创作、离线预览、导入、版本比较、合并和主动提交，不恢复网站编辑器，也不承载评审或讨论。

第一阶段供用户自己在 Mac 的桌面版 Obsidian 中试用。移动端、其他系统安装包、社区插件上架、Zotero 集成、PDF 导出和原位实时排版均不属于第一版承诺。

## 已确认的选择

1. BananaMark 按指定文件夹及子文件夹启用，单篇可以开启或关闭覆盖。
2. 使用 Obsidian 原生编辑器，源码编辑与论文预览分开。
3. 支持单文件和多章节；写作时就建立本地论文，安排章节和共享参考文献。
4. 一篇论文一个文件夹，允许子文件夹。只有章节清单明确列出的正文参与预览和发布。
5. 插件面板管理章节、顺序和论文信息，底层兼容现有 `paper.json`。
6. 写作时提示不兼容的语法，不阻止继续编辑。
7. 插件文献列表管理 `references.yaml`，同时允许直接编辑该文件。
8. 引用补全仅来自当前论文的文献表和章节标签，不建立全库文献服务。
9. 引用可以跳转到对应源码，包括其他章节和文献条目。
10. 在适当语法位置自动补全，也支持快捷键；中文输入法组词期间不打断输入。
11. 全部预览在本机完成，包括 TikZ 和交换图，不向服务器发送草稿来预览。
12. 无效语法保留上次成功预览，显著提示预览尚未更新，定位错误，恢复有效后自动更新。
13. 编辑定位带动预览；用户自由滚动预览不移动源码编辑位置。提供明确的返回源码操作。
14. 支持从 Peerpedia 链接导入已有论文及其章节、参考文献和远程版本绑定。
15. 发布后继续编辑原文件，不为每次修订另建论文副本。
16. 网络操作由用户主动检查、导入、连接账号或提交触发；打开论文与日常编辑不检查远程。
17. 在 Obsidian 内进行三方比较和冲突处理；无冲突部分可自动合并，用户检查确认后写入。
18. 再次提交默认向已绑定且仍开放的提案增加快照，也提供新建提案。
19. 不提供评审、讨论阅读或回复功能，仅保留版本和提案状态。
20. 支持 Codex 等外部工具编辑同一份文件；重新建立索引与预览，有编辑冲突时不静默覆盖。
21. 用户追加确认：先抽出可独立复用的 Peerpedia 文章主题模块。网站与 Obsidian 共享同一来源，模块包含文章字体、配色、排版以及 BananaMark/KaTeX/图形资产依赖；网站导航等外围界面留在网站端。

## Approaches：已讨论的方案

### 采用：扩展 Obsidian 原生编辑器，单独提供论文预览

保持 Obsidian 文件与编辑交互，增加 BananaMark 补全、着色、诊断和定位。独立面板以完整论文上下文渲染。这符合用户选择，并保留普通文件与外部工具之间的协作。

### 不采用：嵌入旧 Peerpedia 专用编辑器

能够较多复用旧界面，但会形成第二套编辑器与文件编辑行为，与用户希望使用 Obsidian 的方向不合。

### 延后：在编辑区原位排版

光标移入才显示源码的实时预览需要额外处理跨段落结构、选区和 Obsidian 自身的排版逻辑。第一版只承诺源码高亮、补全、诊断和独立预览。

## 文件与项目模型

一个本地论文项目对应一个位于 vault 内的根目录。多章节文件必须位于该目录内，允许子目录；不支持引用目录外或通过符号链接引入的章节。

建议单文件约定为 `paper.md`，多文件由 `paper.json` 的有序 `chapters` 清单决定；共享文献为 `references.yaml`。单文件也可以有共享文献，沿用当前 CLI 格式。插件创建 `paper.json` 时给必须存在的字符串字段填空字符串，允许尚未完成的投稿信息；发布前再校验是否齐全。

`paper.json` 只包含 CLI 已识别字段，不写插件专用字段。章节包含稳定 ID、标题和相对文件路径；重命名或排序不改变 ID。章节标题提取遵循网站规则；面板编辑标题时，应明确修改对应标题源码或提示不一致，不能仅更新一个被服务器忽略的显示名称。

建议插件状态放在论文下独立的 `.peerpedia-obsidian/`，记录项目 ID、远程站点与论文标识、基准快照、提案 ID/head、待确认请求和本地恢复记录。凭据不放在这里。最终目录名属于实现细节。

内容格式兼容 CLI，不承诺第一版与 CLI 共用全部同步状态。不得覆盖 CLI 的 `.peerpedia/`。若 CLI 在外部提交，插件在用户下一次主动检查时按远程实际状态处理；不在后台替 CLI 更新凭据或提交状态。

启用范围与论文成员关系是两件事。文件夹启用决定编辑扩展是否工作；显式清单决定哪些文件被预览和上传。关闭某个文件的编辑扩展不将它从论文清单删除，也不跳过发布校验。

建议启用规则优先级为单篇覆盖、最近祖先文件夹设置、全局默认关闭。论文项目不嵌套；检测到嵌套项目时提示选择归属，不悄悄合并两份清单。

## 编辑与语言适配

Obsidian 原生编辑器仍负责文件编辑、撤销、选区和基本 Markdown 行为。第一版以源码视图为支持的写作模式，不承诺与所有 Live Preview 插件组合兼容，不改变无关文件的编辑模式。

通过 Obsidian 官方编辑器扩展和建议窗口接入能力。保留宿主 Markdown 解析器，单独使用 BananaMark 解析结果为其特殊语法添加装饰、高亮和诊断。不能直接注入整套 `bananamark()` 或重复创建另一个 CodeMirror 实例。

补全规则、公式命令表、标签提取和检查尽量复用库中实现。依赖 BananaMark 语法树的补全需要上下文适配；不能声称任意 `completionSources` 可直接适配到原生建议窗口。支持定理环境、公式命令与环境、引用标签、文献条目和受支持代码块。快捷键优先不抢占 Obsidian 的既有操作。

依赖匹配使用宿主兼容的 CodeMirror/Lezer 实例；编辑扩展不能打包不兼容的第二份核心状态和视图库。独立本地渲染组件的依赖不参与宿主编辑器状态。

按当前论文建立跨章节标签与引用索引，支持跳转到文件和范围。重复标签、未知引用和暂时无法解析的范围显示诊断，不跳向任意同名目标。外部文件变化、章节排序和书目修改都使有关索引失效并重建。

写作规则与当前 Peerpedia 方言一致：开启 bibliography/TikZ，关闭 wiki links；普通图片等当前不支持的内容给出兼容性提示。以网站真实规则为准，不能只依赖旧 README 或独立发明兼容规则。

## 本地预览与渲染组件

用户安装插件及必要的本地组件后，断网也能完整预览。组件安装与更新可以由用户明确触发，但每次编辑、打开项目、预览都不能下载资源或联系服务器。

技术建议：用插件控制的独立本地 Node 渲染进程复用网站渲染规则，通信优先使用 stdio，不开放一个无认证网络服务。为用户的 Mac 配备兼容运行时和本地字体/编译资产，不要求运行 Peerpedia Django 服务，也不依赖系统 Python。具体运行时打包方式由实现验证确定。

网页适配、DOM 清理与本地资源地址应与语法和编号逻辑分开。固定一组 BananaMark、TikZ 与字体版本，输出标明所用版本；不静默自动升级渲染引擎。手动检查远程时如检测到不兼容，应明确说明，而不是承诺未知版本间完全一致。

预览拥有全文上下文，包括章节顺序、编号、所有标签与共享书目。界面可以只显示当前章节以提高性能，但必须能浏览全部章节，引用和编号不能按独立文件计算。

先在 `packages/peerpedia-theme/` 提取独立文章主题，提供可安装的包、明确 CSS 入口和资源目录。网站先迁移到该模块，再由插件使用同一产物；不在插件内复制并独立维护网站 CSS。现有全局品牌/色彩变量由网站适配，导航、工具栏和目录壳层继续属于网站。提取以保持网站视觉表现为准，不顺便改版。

采用 Peerpedia 的文章样式，限定在预览容器内，避免全局覆盖 Obsidian 主题。上游样式也需检查作用域，字体声明可以保留必要的全局命名资源，但不能覆盖宿主的普通元素。公式、SVG、字体等依赖均来自本地。预览内容不加载远程图片或其他隐式网络资源；用户主动打开外链不属于后台同步。

编辑更新防抖，昂贵 TikZ 计算使用缓存和独立 worker。渲染请求带修订标识，只显示当前修订的结果；慢的旧结果不能覆盖新结果。限制运行时间、内存/缓存和图数量，取消或丢弃过期任务，不阻塞输入。

任何章节导致本次完整预览失败时，保留上次成功结果，并标明它对应旧修订。首次没有成功结果时显示诊断和空态。过期预览不能作为提交前当前内容已通过检查的依据。

源码定位使预览滚动到相应段落；预览自由滚动不反向改变编辑器。精确映射暂不可得时定位到最近的明确结构并说明，不把近似范围当成精确位置。

## 参考文献面板

条目列表支持新增、查看、修改和删除，保存为 BananaMark 支持的 YAML。保留直接编辑入口。

建议使用 YAML 文档级编辑来保留面板不认识的合法字段和注释，避免将书目缩减成一组固定表单字段。格式错误时先提示修复，不用面板覆盖原文件。

引用键是稳定标识。重命名键应作为明确的重构操作，展示本论文内受影响的引用并一起修改；删除仍被引用的条目需要说明影响。跨论文搜索与 Zotero 同步不在第一版。

## 远程连接与发布

默认站点为 Peerpedia，使用现有访问令牌接口。连接由用户主动发起，可手动验证账号；令牌优先保存在 Mac 系统凭据存储中，不进入正文、vault、项目状态或日志。

未连接账号也能创建论文、编辑、检查和完整预览。公开论文导入不要求登录。首次发布、更新提案由现有权限、许可选择和协议要求控制；插件提供相应入口，不引入浏览器写作或代用户接受网站协议。

仅以下明确操作可以联系服务：用户连接/验证账号、粘贴链接后确认导入、检查远程、准备并确认提交、确认重试。无周期轮询、启动检查、预览上传或自动重试。

导入论文链接获取当前接受版本；导入快照链接保持该快照身份，不默默换成最新版。目标文件夹已有内容时不覆盖，提供新目录。保存原始快照、校验 manifest/内容摘要后建立绑定。历史版本的本地修改在提交前必须与当前远程基准对齐。

建议提交前提供当前文档的预览/差异、论文信息、说明和现有协议要求的字段。按实际情况填写 AI 辅助声明，不能因为插件存在或外部文件变化就自行判定。用户点击明确提交按钮后发送一个冻结请求，日常保存绝不发布。

初次提交是立即公开发表；后续提交创建或更新公开修改提案。用户界面须清楚区分这两个结果。文章接受仍在网站进行。

## 版本状态、冲突与可靠性

分别记录：接受基准、最近已提交快照、当前未关闭提案及预期 head、当前本地文档。未接受的提案不能直接当作新的远程接受基准。

在用户主动检查或准备提交时读远程状态：

- 远程无变化：保留本地内容，继续比较或提交。
- 本地未修改、远程更新：展示更新摘要，用户确认后应用。
- 本地和远程都改变：按共同基准进行三方合并，涵盖正文、章节增删/排序、元数据及参考文献。不能把所有内容简单拼成单一文本后无条件覆盖。
- 当前提案仍开放且由连接账号拥有：再次提交默认追加快照，并带正确的 expected-head。
- 提案被接受：校验并识别已接受快照，更新基准时保留其后本地修改。
- 提案关闭或属于其他账号：不能继续向它追加快照；解释状态并提供基于当前版本新建提案。

合并先形成可检查的候选结果。写入前重新检查本地文档修订和远程基准/head；变化则重新比较。写入保留恢复点，多文件更新使用事务式操作日志，失败可恢复，不能留下不明的半份论文。

提交前持久化精确 payload、幂等键、目标站点和本地修订。收到可验证回执后再完成状态更新。网络中断导致结果未知时不重新生成请求；由用户主动重试相同 payload/幂等键。允许继续保留后续本地修改，但不得把这些修改混入旧请求重试或并行创建重复提交。

外部工具变化需要观察 Obsidian 文件事件。外部修改与本地未提交编辑冲突时，保留双方内容并提示比较。插件面板修改 `paper.json` 或书目也要按版本检查，不能覆盖 Codex 刚写入的新内容。不执行正文或项目文件附带的脚本/命令。

## 验收场景

1. 在未登录、断网状态下新建单文件论文，源码补全、高亮、检查和排版正常；关闭扩展的其他文件不受影响。
2. 新建含多个章节、跨章节定理和公式引用、共享文献及 TikZ 的论文；排序后编号与引用更新，跳转到准确源码。
3. 刻意留下不闭合公式/定理，预览保留上次结果并提示过期；修复后恢复。慢渲染结果不覆盖更新的结果。
4. 直接修改正文、`paper.json` 和 YAML；面板、索引与预览更新，未知合法书目字段不丢失。模拟并发编辑时双方内容可恢复。
5. 导入当前论文和指定历史快照，验证内容与身份；不覆盖已有目录。日常打开、编辑、预览无远程请求。
6. 首次发布后继续编辑原文件，提交提案，再次提交追加同一提案；关闭提案时不能误追加。
7. 构造远程与本地同时修改，包括章节排序和同一文献键冲突；可比较、解决并确认写入，取消保持原文件。
8. 模拟丢失提交响应，主动重试返回同一份快照，期间的新本地编辑不会混入旧请求。
9. 核对正式渲染与本地预览的语义、编号、引用、图形和字体资产。测试使用隔离环境，不向生产站点创建演示论文。
