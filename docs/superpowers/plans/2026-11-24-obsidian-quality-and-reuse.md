# Obsidian 插件质量、性能与复用修改计划

日期：2026-11-24。代码基线：`5b5466825b861f351fd640ee3a54d44d83c4ba1a`，已发布插件版本：0.1.3。

**Goal：** 合并架构、性能、代码质量和复用两轮检查，修复已复现的问题，使插件成为边界清楚的 Obsidian 适配层，同时保留现有稿件保护和发布协议。

**Architecture：** Obsidian 原生编辑器负责编辑；BananaMark 负责语言语义；网站与插件共同消费文章渲染包、主题包；插件只负责宿主适配、本地项目管理和显式远程操作。插件级服务管理共享资源，视图只持有自己的订阅和草稿上下文。

**Tech Stack：** TypeScript、Obsidian API、宿主 CodeMirror、Worker、独立 Node 渲染进程、BananaMark、Vitest、Python 协议验证与现有 GitHub Actions。

**Spec：** [原适配设计](../specs/2026-11-23-obsidian-adaptation-design.md)。本计划补充质量和性能要求，不重新设计出版工作流。

**执行方式：** 每个编号任务作为独立、可验证的改动；先补能暴露问题的测试，再修改实现，最后记录验证结果。当前交付仅为计划，不包含执行、发布或部署。无需追加强制评审流水线。

## 全局约束

- 插件 UI 使用英文；保留紧凑双栏、原生编辑器和独立预览，工程改造不增加按钮、面板或用户配置负担。
- 网站不恢复在线写作。打开、编辑、预览不访问远程；导入、检查、发布仍需用户显式触发。字体、公式及渲染资产可离线使用。
- 保留未保存缓冲区保护、原子替换、目录身份检查、旧 inode 晚写保护、恢复日志、绑定校验、冻结发布请求、幂等重试及回执校验。
- 不修改用户稿件格式，不擅自迁移 CLI 的 `.peerpedia/`；插件状态仍放在 `.peerpedia-obsidian/`。新增缓存与索引均可重建，不成为写入授权依据。
- 所有新增或改动的函数，包括内部辅助函数，显式标注参数与返回类型并保留泛型。JavaScript 使用可检查的 JSDoc；不要用手写声明掩盖实际接口差异。
- 不替换 Obsidian 编辑器，不引入第二套完整 CodeMirror，不要求用户安装 Python、服务器或额外 Node。
- 不引入通用依赖注入框架、全局事件总线或新的项目管理框架。优先复用现有类型、接口和安全机制。
- 安装包体积与运行内存分别测量；服务器部署构建事故不作为插件运行性能差的证据。压缩安装包不是首要任务。

## 已确认的基线与覆盖范围

| 发现 | 证据与边界 | 对应任务 |
| --- | --- | --- |
| P1：插件未进入 CI 和部署检查 | 本地插件检查通过不代表 GitHub 检查覆盖插件 | 1、9 |
| P2：预览取消会终止进程 | 64 章公式密集样例，650 ms 间隔编辑 8 次，5.21 秒中 8 次启动、7 次取消、0 次完成，停输入后完成 | 2 |
| P2：局部修改仍全书诊断与传输 | 64 章约 430 KB 源文，单章编辑诊断约 241 ms；全书 HTML 约 13.9 MB，热渲染约 326–346 ms | 6、7 |
| P2：历史恢复记录拖慢打开 | 临时项目 2,000 条完成记录，暖扫描约 3,055 ms；不是每次按键或普通保存触发 | 3 |
| 资源重复所有权 | 各预览、投稿持有独立 renderer，项目存储、监听及语言计算也有重复；尚未证明是内存泄漏 | 4 |
| 渲染复用接口脆弱 | 网站代码为真实来源，但安装包手工复制 3 个源文件并手写类型；主题已经是共享包 | 5 |
| BananaMark 部分语义重复、依赖内部接口 | 补全重复实现块、环境、公式和引用规则；已有上游补全不能直接跨 Worker 序列化 | 8 |
| 项目发现不一致 | 选择器依赖 Vault 索引中的 JSON，其他入口可直接发现文件；是条件性问题，未确认用户当前环境触发 | 4、9 |
| 冲突表示和 UI 耦合 | 中文展示字符串被当作内部位置标识，再由英文 UI 解析 | 9 |
| CLI 与插件协议实现容易漂移 | Python 和 TypeScript 有各自验证实现；应共享契约样例，而非让插件调用 Python | 1 |
| 真实宿主覆盖不足、格式不统一 | 上次 257 测试通过，2 项可选集成测试跳过；额外格式检查发现 74 个源文件不符合格式 | 1、9 |

性能数字是合成稿、单次测量，不是稳定 p95，也不包含 Obsidian 页面布局。上次类型检查、显式类型检查及生产构建通过。完整安装目录约 200 MiB，主要为离线 Node 和依赖，不能据此推断常驻内存。

## 顺序与依赖

推荐实施顺序：**1 → 2 → 3 → 4 → 5 → 6 → 7 → 9**。任务 8 是独立的上游协作支线，可在任务 1 后推进，但不能阻塞本地故障修复。

- 任务 2 先在现有 renderer 边界修复取消；任务 4 再统一所有权，避免把故障修复和架构迁移混成一次改动。
- 任务 5 先明确网站/插件共享来源；任务 7 的渲染协议修改随后在统一边界落地。
- 任务 6 依赖任务 4 的项目版本和草稿隔离；任务 7 依赖任务 2、4、5。
- 任务 9 收口宿主验收与交付；必要的回归测试随前面任务提交，不拖到最后一次性补。

## 2. 修复预览取消导致的反复冷启动

**文件：** `obsidian/src/preview/controller.ts`、`obsidian/src/preview/renderer-client.ts`、`obsidian/tests/preview.test.ts`、`obsidian/tests/renderer-runtime.test.ts`、`obsidian/tests/submit.test.ts`。

- [ ] 先补失败用例：一次渲染未完成时连续编辑、过期结果到达、切换论文、关闭预览同时投稿、超时和崩溃。
- [ ] 对每个预览消费者采用一个在途任务与一个可替换的最新待处理版本。新编辑撤销旧结果的显示资格，不杀死正在工作的进程，不持续积压版本。
- [ ] 实际崩溃、执行超时或服务销毁才终止 renderer。沿用现有执行超时，起算点为实际执行；排队与消费者取消另行处理，不误算为渲染超时。
- [ ] 预览请求可合并，冻结的发布请求不可合并、修改或被预览取消。明确发布与预览调度顺序，防止连续输入使发布一直排不到。

**验收：** 将完成时机受控的测试中，一批更新最多执行“在途版本＋最新版本”两次；无错误重启时进程启动一次，过期结果不显示。真实连续编辑压力样例不再出现取消导致的反复冷启动，停输入后显示最新版本。已有发布冻结、重试测试继续通过。

## 3. 降低恢复检查成本，保留全部晚写保护

**文件：** `obsidian/src/project/recovery.ts`、`obsidian/src/project/transaction.ts`、`obsidian/src/project/anchored-files.ts`、`obsidian/src/ui/project-panel.ts`；新增 `obsidian/src/project/recovery-index.ts`，扩充 `transactions.test.ts`、`anchored-files.test.ts`、`project-panel.test.ts`。

- [ ] 建立可丢弃、可重建的恢复索引，优先定位未完成及已知需要关注的记录。保留原始日志、原路径和旧 inode；“历史归档”仅指索引分类，不移动、压缩或自动删除旧文件。
- [ ] 论文打开先读取已知状态，历史记录分批后台检查；活跃项目以有界的后续复查继续发现扫描结束后的旧描述符晚写，项目关闭时停止调度。首次建立索引也分批执行；未检查完不声称“全部安全”，利用既有状态区域反馈，不增加新面板。
- [ ] 为只读扫描复用一次目录枚举，避免每条记录重复列出父目录。写入、恢复应用和发布前检查仍使用当前文件/目录身份与摘要验证；后台索引不能跳过安全检查。
- [ ] 业务修改需要确认当前未完成事务时，仍等待相应安全检查；仅把不相关的完成历史扫描移出打开论文的关键路径。异常或受损记录不能因索引遗漏而消失。
- [ ] 覆盖完成后旧描述符继续写入、索引中途崩溃、索引损坏、旧格式日志、权限不足、目录替换及后台扫描期间新事务。恢复通知的产生与现有保护等价。

**验收：** 2,000 条完成记录不阻塞论文首次显示；基准分别报告首屏可用时间和后台完整检查时间，并检查扫描分批让出执行权。缓存损坏可重建，晚写仍被发现，没有自动丢弃的恢复材料。磁盘长期增长暂时保留为明确成本，不靠牺牲恢复能力解决。

## 4. 统一项目发现和资源所有权

**文件：** `obsidian/src/main.ts`、`obsidian/src/host/writing-projects.ts`、`obsidian/src/host/vault-store.ts`、`obsidian/src/host/suggest.ts`、`obsidian/src/preview/runtime.ts`、`obsidian/src/ui/preview-view.ts`、`obsidian/src/ui/project-panel.ts`；新增 `obsidian/src/host/project-session.ts`、`obsidian/src/preview/render-service.ts`。

- [ ] 插件持有按规范化根路径复用的 `ProjectSession`，统一项目发现、磁盘快照、版本和文件监听；各视图订阅，最后一个订阅释放时清理资源。复用现有 `ProjectStore`，仅为实际调用增加必要的小接口。
- [ ] 项目选择器、跟随当前文件、创建与导入后的识别全部调用同一发现入口；兼容 `paper.json` 未被 Vault 索引的情况，不改变用户的 Obsidian 全局文件设置。
- [ ] 磁盘快照与视图草稿分开。草稿键包含视图身份和版本，不能把两个分屏对同一文件的不同未保存内容混成一个项目版本，也不能隐式把预览草稿当作发布内容。
- [ ] 一个插件级渲染服务管理一个 Node 进程和有界队列，视图及发布各有消费者身份。关闭一个视图仅释放该订阅；空闲且无任务 60 秒释放进程，插件卸载立即清理。
- [ ] 语言计算按交互补全与项目诊断最多保留两个 Worker 通道，复用不可变项目输入和版本规则；避免重诊断堵住补全。暂不为减少一个 Worker 引入跨线程共享内存等复杂机制。
- [ ] 统一在服务边界销毁监听器、定时器、Worker 和进程；从 `main.ts` 移出相应编排，不进行无关的全文件重构。

**验收：** 多个预览和投稿共用一个 renderer；同项目的应用层文件监听不随视图数成倍增长。分屏草稿、跨项目切换、关闭再打开、空闲重启、卸载和崩溃恢复均有测试；重复开关 50 次后资源计数回到基线。记录实际内存趋势，不把“进程数下降”当作已经证明无泄漏。

- [ ] 包内声明自身资产与运行依赖，打包通过依赖闭包产生离线成品、版本和来源清单。无需为此公开发布 npm 包。

**验收：** 改动一处共享渲染实现能同时被网站与插件消费；包的类型、资源、依赖均可独立检查。网站现有测试和插件渲染测试通过，真实 UI 保持一致，无在线编辑器回归。

## 6. 让语言检查按实际变更失效

**文件：** `obsidian/src/language/analysis.ts`、`obsidian/src/language/diagnostics.ts`、`obsidian/src/language/worker.ts`、`obsidian/src/language/worker-protocol.ts`、`obsidian/tests/language.test.ts`、`obsidian/tests/language-worker.test.ts`。

- [ ] 复用已有源文扫描缓存，为章节诊断增加源文摘要和外部标签语义签名。签名包含标签存在性、重复计数、有效性及相关路径，不只使用标签名称集合。
- [ ] 分开局部检查与项目级依赖：普通段落修改复用未变章节结果；标签、文献、章节成员或编号语义改变时重新检查受影响部分。初版允许对全局依赖保守失效，不先建设复杂依赖图。
- [ ] 缓存键包含项目身份、语言配置和草稿版本；设定容量边界，项目关闭时释放。旧 Worker 响应仍按版本拒收。
- [ ] 覆盖重复/缺失标签、跨章引用、章节删除重排、文献更新、CRLF、Unicode 规范化、多个草稿及配置变化；与完整重算结果逐项对比。

**验收：** 不改标签的单章普通编辑只重做该章局部诊断，重复相同输入不再全章检查。正确性以完整重算为参照；64 章基准以至少 5 次暖运行的中位数和范围报告，诊断耗时降低 50% 为优化目标，未达到则记录瓶颈，不用降低检查覆盖率达标。

## 7. 增量传输和更新预览，保留全书语义

**文件：** `obsidian/renderer/protocol.ts`、`obsidian/renderer/main.ts`、`obsidian/src/preview/renderer-client.ts`、`obsidian/src/preview/controller.ts` 及实际消费页面模型的预览视图；扩充 `renderer-runtime.test.ts`、`preview.test.ts`、`navigation.test.ts`、`scroll-link.test.ts`。

- [ ] 为协议增加显式版本，以及 full/delta 两类成功响应。delta 包含基础 revision、新 revision、变化页面、删除页面、页面顺序和必要目标元数据；客户端只有在基础版本吻合时应用。
- [ ] renderer 仍按全书上下文解析编号和引用，再按最终页面摘要决定返回哪些页面；章节重排、交叉引用或文献变化可能影响多页，不强求每次只更新一页。
- [ ] 客户端重建与完整渲染等价的页面模型，保留未变页面对象及 DOM；来源跳转、目标位置、滚动同步使用当前版本。发布路径始终取得冻结文稿对应的完整结果。
- [ ] 协议不匹配、缓存淘汰、服务重启或基础版本缺失时请求完整结果；不应用一半 delta，不展示跨论文缓存内容。
- [ ] 覆盖新增/删除/重排章节、跨章编号、文献变更、连续编辑取消、切换项目、崩溃后重连和旧客户端/新 renderer 不匹配。

**验收：** 同一修订的增量重建结果与完整渲染逐项等价；只影响一页时不再传整本书约 13.9 MB HTML，传输量为变化页面与元数据之和。未变页面不重复替换 DOM；记录真实 Obsidian 的布局和输入延迟，区分计算、传输和显示成本。

## 8. 收敛 BananaMark 补全与公共接口（独立上游支线）

**文件：** `obsidian/src/language/completion.ts`、`obsidian/src/language/index.ts`、`obsidian/src/language/upstream.d.ts`、`obsidian/src/host/suggest.ts`、相关语言测试；BananaMark 的实际维护仓库需在执行时定位并确认。

- [ ] 先建立补全与扫描契约样例，区分上游语义和宿主适配。保留 Obsidian 的 `EditorSuggest` 与原生编辑扩展，不直接注入完整 `bananamark()`。
- [ ] 与上游统一纯补全结果接口：候选标签、替换区间、插入文本及光标位置；以现有插件候选类型为基础。上游 CodeMirror 包负责自己的编辑器操作，插件负责 Obsidian 插入，环境/块/公式/引用规则只在一处维护。
- [ ] 若上游存在无法用纯文本操作表达的 snippet 行为，明确扩展可序列化操作类型并补用例；不能把带 `EditorView` 回调的 `Completion.apply` 直接传过 Worker，也不能静默丢失行为。
- [ ] 将确实使用的扫描能力变为上游公共导出，逐个替换 `bananamark/internal/*` 和手写接口。项目路径、跨章重复标签、草稿身份及重命名仍是插件职责。
- [ ] 覆盖数学环境、已有结束标记、定理简写、参数、引号/缩进、代码围栏、IME、CRLF、Unicode、自动/显式触发、引用完整后缀替换和旧版本响应。
- [ ] 隔离当前显式触发使用的 Obsidian 兼容逻辑；核实受支持公共 API，不能假定存在。若仍需兼容回退，在最低支持版本与当前测试版本验证。

**依赖与退出条件：** 不修改 `node_modules`，不复制一份上游语义来声称完成复用。上游公共 API 暂不可用时，先将现有行为集中到单一适配边界、锁定版本并运行契约测试；明确标记“语义去重待上游”，不阻塞任务 2–7，也不将该支线报为完成。

## 9. 清理 UI 数据耦合，完成真实宿主与发布验收

**文件：** `obsidian/src/remote/merge.ts`、`obsidian/src/remote/merge-bibliography.ts`、`obsidian/src/remote/merge-journal.ts`、`obsidian/src/ui/merge-view.ts`、`obsidian/tests/merge.test.ts`、`obsidian/tests/network-boundary.test.ts`、`obsidian/tests/offline-journey.test.ts`、`obsidian/scripts/validate-offline-host.py` 及 Help/安装说明。

- [ ] 在现有 `MergeConflict.kind` 基础上用带类型的章节/字段/文献位置替代可翻译字符串；稳定冲突标识与英文文案分离，UI 统一格式化。检查已存合并状态，必要时只读兼容旧字段，不能使待恢复事务失效。
- [ ] 新增少量跨边界旅程：创建或导入→项目发现→切换→预览；文献编辑；异步任务完成前关闭弹窗；外部重命名与分屏脏缓冲区。选择器测试实际调用枚举入口，不只手动调用选中回调。
- [ ] 在隔离 Vault 中验证最低支持 Obsidian 与当前测试版本；使用真实安装包和一次性本地服务跑导入、预览、发布回执旅程，断网验证本地写作与渲染。不得使用生产账号或用户文章测试发布。
- [ ] 用任务 1 的同一组样例重测连续编辑、单章变更、恢复记录和多窗口资源；补充真实 UI 耗时及长时间内存趋势。报告改善和仍存在的成本，不混用机器或运行时给出夸大的百分比。
- [ ] 统一插件格式与格式检查，单独提交机械变更，与功能修改分开。新增及修改函数全部通过显式类型检查；不以文件行数作为拆分的唯一理由。
- [ ] 核对 Help 与实际成品一致，包括安装目标、生产站点地址、连接、导入及预览入口。若流程未变，避免无意义重写文档和新增 UI 提示。
- [ ] 最终验证插件全套测试、类型/格式、打包与离线启动，以及涉及共享渲染的现有网站检查。正式发布时再确定补丁版本并更新资产与校验信息，不覆盖已发布 0.1.3 的不可变资产。

**验收：** 必需检查无失败、无用跳过代替成功；安装包从干净 Vault 可完成核心旅程；英文 UI、紧凑双栏与网站文章视觉一致。实现阶段交付改动清单、基准对比、剩余问题和明确的发布就绪结论。

## 最终检查重点

1. 复用是否真正消除了第二份语义实现，而非只加包装类？网站和插件是否指向同一个源包？
2. 性能改善是否来自减少重复计算和工作量，而不是省略检查、丢弃恢复记录或忽略旧版本？
3. 共享进程、项目服务和缓存是否保留草稿隔离、发布冻结及消费者取消边界？
4. 历史日志、绑定和合并状态是否仍可读取、恢复？任何派生索引损坏是否均可安全重建？
5. CI 是否验证实际成品并真正阻止失败发布？真实宿主缺项与上游依赖是否被如实列出？

## 暂不纳入

- 推倒重写插件、重新设计 UI、恢复网页写作、扩展到移动端或新增平台。
- 为缩小包体改写 BananaMark、取消离线能力、取消进程隔离或要求用户安装额外运行环境。
- 自动清理恢复材料，以及在缺乏安全边界证明时改变日志保留策略。
- 将 Python CLI 整体搬入插件，或为共享少量协议逻辑引入跨语言运行时。
- 当前计划阶段修改线上服务、用户 Vault、凭据或安装包。
