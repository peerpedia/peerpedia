Download and install

Download Peerpedia {{ project_version }} for Obsidian — Mac with Apple silicon · SHA-256 checksum

This package is for desktop Macs with an Apple M-series chip. It requires Obsidian 1.15.1 or newer and was tested on macOS 15.6.1. Intel Macs, Windows, Linux and mobile are not supported by this package. It includes the renderer, fonts and diagram tools; no separate Node.js, Python or TeX installation is needed.

  1. Install Obsidian and open or create the vault where you want to write. A vault is a folder on your computer.
  2. Download the ZIP above and extract it in Finder. The extracted peerpedia folder contains three files: main.js, manifest.json and styles.css. The renderer, fonts and diagram tools are embedded in these files.
  3. Open your vault folder in Finder. Press ⌘⇧. to show hidden files. Open .obsidian and create a plugins folder if it does not exist. If you use a custom configuration folder, use its plugins folder instead.
  4. Copy the extracted folder into .obsidian/plugins/peerpedia/. You should find manifest.json, main.js and styles.css directly inside that folder. If Peerpedia is already installed, follow Update the plugin below first.
  5. Reopen the vault. In Settings → Community plugins, enable community plugins and turn on Peerpedia. This is a manual installation, so it will not appear through searching the community directory.
  6. Press ⌘P to open the command palette and search for Peerpedia. The commands below are available there.
Verify the download

Save the ZIP and checksum in the same folder. In Terminal, change to that folder and run:

shasum -a 256 -c peerpedia-obsidian-{{ project_version }}-darwin-arm64.zip.sha256

The result should say OK. A successful check confirms that the archive matches the published checksum.

See Obsidian’s manual plugin installation documentation for the vault plugin-folder convention.

Create or import a paper

Start a new manuscript

Press ⌘P and choose Peerpedia: Create paper. Enter a new folder name within the vault, choose Single file or Multiple chapters, and complete the form. Open the resulting Markdown file to write. No account is needed for local writing or preview.

Download an existing paper

Choose Peerpedia: Import paper from Peerpedia. Use {{ site_url }} as the site, paste the paper’s website URL, and choose a new destination folder within the vault. A paper link imports the latest accepted version; a snapshot or version reading link imports that exact version. Public papers can be imported without signing in.

Keep paper.json, the Markdown chapters, the shared bibliography and the hidden .peerpedia-obsidian/ folder together. The hidden folder records the website binding and recovery information. Back up the whole paper folder.

Open the Peerpedia preview

  1. Open a Markdown chapter belonging to your paper.
  2. Press ⌘P, search for Peerpedia: Open paper preview, and select it.
  3. The Paper preview tab opens beside your source. It uses the same article renderer and shared styles as the website, including equations, theorem blocks, diagrams and references.

To show the compact chapter list, choose Peerpedia: Manage paper. This opens the plugin’s Manuscript panel on the right. Its Open preview action is below the paper title, beside Publish.

Obsidian’s own Outline panel shows headings in the current file and has no Peerpedia preview button. Its built-in reading mode and ⌘E also do not render the full BananaMark extensions. Use the command above even when the Manuscript panel is closed.

The directory and preview follow the paper you are editing. Use the preview’s chapter selector to read another chapter, or Go to source to return to its source. You can assign a shortcut to Peerpedia: Open paper preview under Settings → Hotkeys.

Chapters, formatting and references

Use Obsidian’s Source mode to edit BananaMark. In Settings → Peerpedia, enable writing assistance for the relevant folder or individual files. Individual file rules take priority over folder rules. The plugin supplies syntax colors, completion, diagnostics and reference navigation. See Writing and formatting for the supported syntax and examples.

In Manuscript, click a chapter to open it. Use + to add one, drag chapters to reorder them, or open a chapter’s … menu to rename or remove it. Removing a chapter from the paper leaves its source file in the vault. A chapter’s first heading supplies its published title.

References opens the shared bibliography. Search by title, author or citation key. Choose Edit YAML source to add, edit or remove entries in the shared file. Saving checks the YAML structure; invalid YAML keeps the dialog and your draft open without changing the file. Preview checks citation and publication rules. Use the Rename citation key button beside an entry, then Find citations and Confirm rename, to update its citations across the paper. Direct changes to keys or deleted entries in YAML do not automatically rewrite citations. Paper details holds the title, authors, abstract, subjects and license. Click the paper title to switch between papers.

Editing and preview work offline and do not upload your changes. If a preview cannot render, its status explains the problem and retains the last successful preview until the source is corrected.

Connect your account

An access token lets the plugin submit through your Peerpedia account. You only need it when you are ready to publish or propose changes.

  1. Sign in on the website, verify your email and accept the submission agreement.
  2. Open Account → Access tokens, confirm your password, and create a token. Enable Also allow publishing new papers to publish your own new work; proposal permission is enough to submit revisions. For a Google-only account, use Account → Add a password by email first.
  3. In Obsidian, choose Peerpedia: Connect or disconnect a Peerpedia account. Enter {{ site_url }} and paste the token into the token field. Choose Connect and verify account.
  4. Check that the account and site are correct. Later, the paper’s … → Peerpedia account menu opens the same connection panel.

The token is shown only once on the website. Keep it out of notes, chats and source repositories. The plugin stores it using Obsidian secret storage; its settings contain a secret reference rather than the token. If secret storage is unavailable, the connection lasts for the current session only. Revoke tokens from the website’s Access tokens page.

Publish a version

  1. Check the manuscript in Paper preview and complete Paper details.
  2. Choose Publish in the Manuscript panel. Select the submission type, explain the change, and indicate whether AI assisted you.
  3. Choose Review submission. Inspect the destination, account, publication details and rendered manuscript. Expand Exact source to submit to inspect the frozen source.
  4. Choose Confirm submission only when that version is ready. The result links to the public snapshot.

Publish a new paper makes the initial paper public. Create a new proposal creates a public proposed revision; it changes the accepted text only after the corresponding author accepts it on the website. Add a snapshot to the open proposal updates a linked pending proposal with another frozen version.

If confirmation is interrupted, use Resume submission and Retry saved submission. A retry sends the exact saved request, even if you have edited locally since. It does not publish a second copy. Finish from saved receipt completes a verified receipt locally when available.

Check website changes

Open Versions and remote changes at the bottom of the Manuscript panel. Choose Check remote version to read the accepted version and linked proposal status. Use Compare accepted version to inspect changes before bringing them into your working copy.

Resolve conflicts with Use local, Use remote, or Edit result. Review the result before Confirm merge. If either version changes during the comparison, reopen it. Opening a file or typing does not automatically download or publish anything. Website reviews, discussion and acceptance remain on the website.

Update or remove the plugin

  1. Back up your manuscript folders, including hidden binding and recovery files. Disable Peerpedia in Settings → Community plugins.
  2. Move the existing .obsidian/plugins/peerpedia/ folder to a backup location outside plugins/. Copy the new complete peerpedia folder into its place.
  3. If the old plugin folder contains data.json, copy that file into the new plugin folder to retain your writing scope and account settings. Keep the original backup. When upgrading from 0.1.3, reconnect your account once to save the token in Obsidian secret storage. The new plugin does not read or remove the old macOS Keychain entry. If you no longer have the token, create a new one on the website.
  4. Reopen the vault, enable Peerpedia, and open a chapter with Peerpedia: Open paper preview. Confirm the version in Community plugins. Manual packages must be updated manually.

To roll back, disable the plugin and restore the backed-up plugin folder. To remove saved credentials, use Peerpedia account → Disconnect and remove local credentials before removing the plugin. Removing the plugin leaves manuscripts in the vault and does not remove anything already published.

Troubleshooting

There is no Open preview button.

Use ⌘P → Peerpedia: Open paper preview. To restore the right panel, run Peerpedia: Manage paper. Check that you are looking at Manuscript, not Obsidian’s Outline.

The command palette has no Peerpedia commands.

Check the active vault, the enabled plugin switch, and the folder path. manifest.json must be at .obsidian/plugins/peerpedia/manifest.json, not inside an extra nested folder. Reopen the vault after installation.

Formulas or theorem blocks appear as raw text.

Open the dedicated Paper preview tab, rather than Obsidian’s reading mode. For source colors and completion, enable the folder in Settings → Peerpedia and use Source mode.

The plugin or preview cannot start.

Check that this is an Apple silicon Mac running Obsidian 1.15.1 or newer and that all three plugin files came from the same release. Reinstall the complete package using the update steps. Report the displayed error through the issue tracker.

The account or submission needs attention.

Check the token’s expiry and permissions, verified email and agreement status. For a pending retry, reconnect the same site and account. For a stale version, check and compare the latest accepted version before submitting again.
